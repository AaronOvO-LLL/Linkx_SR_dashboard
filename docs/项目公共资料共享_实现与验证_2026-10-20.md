# 项目公共资料共享

已实现：同一项目内，「项目基本情况」「物业信息」的公共字段只保存一份，各管家读取同一答案。页面自动保存后，其他管家刷新即可使用。新添加的管家也能立即读取已有公共资料。

## 范围与填写规则

- 共享由公共字段包的 `value_scope: "project"` 指定。目前仅 `common_project.json`、`common_property.json` 使用该设置。
- 其他字段，包括同样复用定义的「项目资料」，仍按管家独立保存。
- 各管家仍可配置各自的必填要求和字段显示范围。资产管家目前只引用公共项目名称，不会因此多出物业表单。
- 项目来源统一为内部、外部、渠道、重点四项。重点与渠道没有自动转换关系。
- 人工修改公共资料会影响同项目的全部管家。AI 只补充空的公共字段，不覆盖已有公共答案；人工确认和历史冲突检查与写入位于同一 SQLite 写事务内。
- 不同项目、不同分部之间不共享资料；现有项目所属分部的访问检查继续生效。
- 工作台记录标题与表单中的项目名称仍独立管理，维持原有语义。

## 升级与旧资料

停止旧服务并重新启动工作台即可加载代码并自动执行 v4 迁移。不要让旧版本和新版本同时写同一数据库。

含历史答案的数据库在迁移前会自动生成一致备份：`workbench/data/workbench.db.pre-shared-v4.bak`（使用自定义数据库路径时，备份跟随该路径）。备份包含 WAL 中已经提交的内容，迁移重试不覆盖原备份。

迁移以项目、字段为单位合并：

1. 只有一份非空答案，或各管家答案相同：提升为共享答案；相同答案优先保留人工确认状态。
2. 存在不同非空答案：共享值暂留空，填报页显示原管家、时间、答案和原文依据。用户可点击「采用这份答案并共享」，也可重新填写。冲突解决前，引用该字段的管家不能生成材料，即使该字段在当前管家中是选填。
3. 原产品级记录保留；冲突候选快照和最终选择继续留存，后续修改追加历史记录。
4. 清空共享字段后，不会再从旧产品副本回填。未解决冲突不能靠清空绕过。

本次对本机现有数据库进行了只读复制、在副本上升级的演练：554 条原答案全部保留，形成 135 条共享答案、10 处待确认冲突；25 个已有管家的填报页均返回 200，数据库完整性检查通过。原 `data/workbench.db` 未被这次演练修改；这些冲突将在正式升级后由用户选择。

## 生成材料与项目生命周期

公共资料每次有效修改会增加项目公共资料版本。校验结果、生成记录和导出包都关联版本。旧校验不再作为当前通过依据；旧材料显示「公共资料已更新，需重新生成」，查看、下载和打包入口会拦截过期内容。旧文件保留用于追溯。

生成期间若公共资料改变，本次材料也会判为过期；打包期间若资料改变，该包不会登记为可下载的最新包。重新生成后可正常查看、下载和打包。

复制项目会复制公共答案和待确认冲突，副本随后独立修改；彻底删除项目会清理其公共答案、冲突、历史和版本，不影响其他项目。

## 主要代码位置

| 文件（相对 workbench） | 作用 |
|---|---|
| `config/field_packs/common_project.json`、`common_property.json` | 公共字段与项目级存储标记 |
| `config/products/*/fields.json` | 各管家的必填、显示范围及字段模型版本 |
| `core/fieldmodel.py` | 公共包存储归属装配，产品覆盖不能改变该归属 |
| `core/db.py`、`core/migrations.py` | 一致备份、v4 表结构及旧数据合并 |
| `core/repo.py` | 公共/专属读写合并、事务保护、冲突审计、项目复制删除、版本检查 |
| `services/survey.py`、`app.py` | 人工保存、提取和历史答案选择入口 |
| `core/validate.py` | 冲突校验与各管家独立必填校验 |
| `core/generate.py`、`core/packaging.py`、`services/artifacts.py` | 材料和导出包的版本保护 |
| `templates/review.html`、`preview.html`、`result.html`、`static/app.js` | 共享提示、冲突选择及过期状态 |

后续添加新的项目级字段可以沿用 `value_scope`。如果把已存在的专属字段改为项目级，需要新增迁移版本并明确旧答案合并策略，不能修改已发布的 v4 迁移。
