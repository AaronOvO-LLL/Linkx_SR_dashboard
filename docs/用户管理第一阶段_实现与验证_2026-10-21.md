## 身份与权限约定

- 新账号由管理员分配，用户名为 3–64 位英文字母、数字及 `_.@-`，首位须为字母或数字，按小写唯一保存。密码为 8–128 位，使用 Werkzeug PBKDF2-SHA256 哈希保存，不回显哈希或明文。
- 管理员是系统管理员，可跨分部访问所有项目；普通账号可访问自己创建的私密项目和本分部历史共享项目。账号移到其他分部后仍可访问自己的私密项目。
- 个人新建/复制项目固定为私密，当前阶段没有公开或邀请成员入口。客户端提交的创建者、姓名和 visibility 参数不被采纳。
- 原分部入口继续兼容共享项目，也仍可新建/复制分部共享项目；页面明确提示：需要个人私密项目时，应退出并以个人账号登录。该入口不能管理个人账号，不能访问任何个人私密项目。
- 旧项目显示“历史项目（未记录个人创建者）”。历史负责人字段不是创建者，未据此自动认领项目。
- 停用、修改账号资料/角色/分部、重置密码都会递增凭据版本，旧会话下次请求失效，不降级成分部会话。本人改密保留当前浏览器会话、撤销其他会话。
- 个人登录和个人账号 POST 请求校验 CSRF，表单、字段自动保存和聊天均已配套。个人账号 GET 退出返回 405，页面用带 token 的 POST 退出。分部兼容会话保留原写接口策略；未将它描述为完整的个人账号安全机制。
- 同用户名在五分钟窗口内最多尝试五次登录，成功清除计数；失败计数保存在数据库。受保护页面/文件响应使用 `Cache-Control: no-store`，录音仍支持范围播放。
- 项目权限检查早于读文件、转写恢复及其他业务操作；录音还要匹配路径中的项目 ID。已下线材料类型在项目授权后直接返回 404，修正了原自检中先被材料状态检查重定向的情况。

## 开始使用与升级

1. 停止旧工作台进程，更新整套代码。禁止新旧版本同时写同一数据库。
2. 确认已有数据库、录音、输出和导出目录有备份。首次 v5 迁移前会自动使用 SQLite backup 生成一致快照，包含已提交 WAL，命名为 `<数据库路径>.pre-users-v5.bak`；重复启动不覆盖。若旧库还未升级 v4，共享资料迁移及其备份也会按原规则执行。
3. 在 `灵石解决方案工作台/workbench` 下运行管理员初始化命令。Windows 使用现有虚拟环境：

   ```powershell
   .\.venv\Scripts\python.exe manage_users.py create-admin --username admin --name "管理员" --dept dept1
   ```

   Linux 可用现有虚拟环境的 `bin/python` 执行同一脚本。按终端提示输入并确认新密码，密码不放在命令行。用户名 `admin` 仅是示例；重复用户名不会覆盖旧账号。此命令也可由有本机权限的运维创建另一个管理员，用于账号恢复。

4. 按原启动方式启动服务，打开登录页，使用新建的个人管理员账号登录，进入“账号管理”为同事创建账号。没有默认管理员密码。个人账号所属分部已固定，无需登录时另选分部。
5. 普通用户登录后创建项目，核对创建者和“私密”标识。旧项目仍按所属分部共享；旧分部口令位于登录页折叠的“原分部入口（兼容历史项目）”。

生产服务继续沿用原有 `LS_SESSION_SECRET`、HTTPS/Cookie 设置和私有录音存储配置。本轮检查了仓库 nginx 配置：请求统一代理到 Flask，没有直接映射 `data/uploads/outputs/exports` 的公开文件目录；未核实或修改线上实际配置。

### 回退

停止新服务后，先另存升级后的数据库及运行文件，再用升级前一致备份恢复数据库并切回对应旧代码。不要把旧代码直接连到已经创建了私密项目的新库：旧代码没有个人权限检查，可能按分部暴露这些项目。恢复旧备份不包含升级后的新账号和新项目，须提前保留用于后续恢复。原录音和材料文件并不包含在数据库备份中，完整恢复需要配套的运行目录备份。
