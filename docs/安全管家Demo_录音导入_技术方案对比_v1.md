# 录音导入 · 转写技术方案对比 v1

> 文档性质：选型决策支持文档（技术方案 Agent 产出，待需求负责人拍板）
> 编制日期：2026-09-15
> 适用场景：单次 1–2 小时踏勘录音，Windows 单机 Flask 应用
> 价格口径警示：以下价格均来自公开文档检索（2026-09-15），**标注「待核实」的项不得直接用于对外报价或预算承诺**；正式选型前须以厂商最新计费文档为准。

## 1. 先说结论

| 问题 | 结论 |
|---|---|
| 费用是不是选型约束？ | **不是。** 2h 录音单次转写成本区间为 ¥0–¥9.2，主流方案集中在 ¥0.6–¥1.6。差一个数量级也仍低于人工整理成本，不应作为首要判据 |
| 真正的选型判据是什么？ | ① 能否免去对象存储中转 ② 是否原生支持手机 m4a 直传（免 ffmpeg）③ 热词表能力（对应"业务名词矫正"）④ 说话人分离 ⑤ 时长上限 ≥4h |
| **推荐主通道** | **火山引擎 Seed-ASR 2.0 录音文件识别**（0.8 元/小时，异步任务，最贴近需求）或 **阿里云 Paraformer v2 / Fun-ASR**（0.288–0.79 元/小时，最便宜且文档最全） |
| **推荐备通道** | **本地 FunASR（SenseVoice-Small + cam++ 说话人）**——理由不是省钱，是**音频不出内网、无对象存储环节** |
| 明确不建议 | **多模态 LLM 直转音频**。2h 音频折算约 90 万 audio token（按阿里云 12.5 token/秒折算），成本高、上下文极长、且拿不到时间戳与说话人结构 |
| 架构要求 | 无论最终选谁，**必须封装为 `core/asr.py` 的 provider 接口**，上层逻辑不得感知厂商。切换成本 = 一个 provider 实现 |

## 2. 被低估的真实成本：音频怎么到云端

这是本方案里最容易估错工作量的一步，单独成章。

| 厂商 | 是否支持提交本地文件 | 结论 |
|---|---|---|
| 阿里云 智能语音交互 | **明确文档写明"不支持提交本地文件"**，必须提供公网可访问 URL；URL 只能用域名、不能含空格、尽量避免中文 | 必须对象存储中转 |
| 阿里云 听悟（离线转写） | 同样要求公网可访问的 URL | 必须对象存储中转 |
| 火山引擎 LAS 语音转文字算子 | 文档写明"目前仅支持公网 URL" | 必须对象存储中转 |
| 腾讯云 CreateRecTask | 支持 `SourceType=0`（Url）与 `SourceType=1`（本地语音数据 base64）两种 | **待核实**：社区资料显示 base64 直传路径存在约 60s / 3MB 的时长体积上限，2h 录音大概率仍需走 Url 方式 |

**由此得出的必然结论：**

> 无论选哪家云厂商，**2h 录音几乎都必须先上传到对象存储（COS / OSS / TOS）取得可访问 URL，再提交转写任务**。这带来三项新增工程负担：
> 1. **对象存储 SDK 依赖**（打破当前"唯一 pip 依赖 flask"的约束）
> 2. **两套密钥管理**（对象存储 AccessKey + ASR 密钥）
> 3. **音频离开内网**（涉客户敏感信息，需隐私决策）
>
> 本地 FunASR 通道的价值正在于**结构性消除这三项**，而非省钱。

**降级路径（优先核实，可省掉对象存储）：**
- 核实项 A：腾讯云 CreateRecTask 的 base64 直传在 2h / ~120MB 音频下的真实上限。若可行，则链路最短。
- 核实项 B：部分厂商的"极速版"接口采用 HTTP 二进制直传（腾讯云录音文件识别极速版为 HTTPS POST 音频原始数据，限制 100MB / 2小时）。2h 录音恰在上限边界，需实测。
- 若 A/B 均不可行 → 采用对象存储中转，或改用本地 FunASR 通道。

## 4. 推荐的组合方案

**分层设计，接口统一，厂商可换：**

```
core/asr.py  ── provider 接口：(音频文件) → TranscriptResult
                 │
    ┌────────────┼────────────┬──────────────────┐
    ▼            ▼            ▼                  ▼
cloud_volc   cloud_aliyun  cloud_tencent    local_funasr
（主通道）     （备选）      （备选）          （隐私通道）
```

| 层 | 选择 | 理由 |
|---|---|---|
| 主通道 | 火山 Seed-ASR 2.0 或 阿里云 Fun-ASR | 异步任务模型天然契合"上传后不阻塞"；热词能力对应"业务名词矫正"；成本可忽略 |
| 隐私通道 | 本地 FunASR SenseVoice-Small | 当录音含高敏感内容、或不允许出内网时启用；CPU 即可跑 |
| 术语矫正 | **两级**：① 提交时传 ASR 热词表（如"消控室｜100"强制替换）② 取回后做配置化纠错映射（`asr_terms.json`） | 不依赖单一厂商能力，厂商换掉矫正表仍可用 |
| 文本精修 | 复用本项目既有 LLM 通道（当前默认关闭） | 避免与厂商增强算子绑定；且 §6.4 已要求提取结果须经结构校验 |
| 不做 | 多模态 LLM 直转音频 | 无时间戳/说话人结构、成本高、上下文过长 |

**选型判据优先级（按此顺序评估）：**

1. **能否免去对象存储中转**（核实项 A/B）——省掉一整条链路和一套密钥
2. **是否原生支持 m4a 直传**——免引入 ffmpeg 二进制
3. **热词表是否支持"强制替换"级别的权重**——直接决定"消控室/恒益"类词的矫正效果
4. **是否支持说话人分离**——决定"转写后校文本"这一步是否可做
5. 时长上限与并发是否满足 ≥4h、多项目并行
6. 单价（实测已证明不是约束）
