# 资产管家字段与流程接入说明

日期：2026-10-09。产品标识：`asset_butler`，首版版本：0.1.0。

2026-10-20 更新：工作台 v0.2.0 中，资产管家字段模板升至 0.2.0，项目名称与同项目的其他管家共享；其余资产客户字段仍独立保存。下方首版验证结果保留当时的验证时间与范围，当前公共资料共享的验证见《项目公共资料共享_实现与验证_2026-10-20.md》。

## 已确认范围

按用户要求，沿用安全管家的「录入 → 信息核对 → 结果预览 → 材料生成」流程，在现有工作台中新增资产管家。字段依据为[灵石资产管家（SpaceUp）客户信息收集](https://space-up.feishu.cn/share/base/form/shrcnIfk58GSobJKAHqW5aIt6Md)。本次已通过浏览器读取题目、选项、必填标记和填写提示。

用户确认最终产出物暂时未定、不急。本次只提供一份事实型「客户调研结果」用于验证生成、查看和ZIP下载，最终方案类、报价类、实施类材料均待后续定义。该清单可在产品目录内独立调整。

## 字段映射

保持源表14题、8个必填项，按5个业务分组展示。项目名称复用公共字段包，仅在资产管家覆盖为选填，并移除公共包中与本表不符的6个字段。

| 原题 | 工作台字段 | 类型 | 必填 | 口径 |
|---|---|---|---|---|
| 1 姓名及联系方式 | submitter_contact | 多行文字 | 是 | 本次信息提交人，区别于客户联系人 |
| 2 客户名称 | asset_customer_name | 文字 | 是 | 客户公司/机构全称 |
| 3 客户所在城市 | asset_customer_city | 文字 | 是 | 保留明确提到的城市 |
| 4 项目名称 | project_name | 文字 | 否 | 本项目的具体名称，与同项目其他管家共享；不等同于工作台记录名 |
| 5 在运营项目数 | operating_project_count | 数字 | 否 | 租赁经营型项目，非负整数；原文明示0则保留，未知留空 |
| 6 经营性资产业态 | asset_types | 多选 | 是 | 7个源表选项，支持其他业态说明 |
| 7 在租客户数量 | tenant_scale | 单选/详细说明 | 是 | 5档及「其他/详细说明」，多个园区合计；未开业可记录预估 |
| 8 数字化建设现状 | digitalization_status | 多行文字 | 否 | 系统、供应商、上线年份、历史预算、使用情况 |
| 9 痛点或强烈需求 | asset_pain_points | 多选 | 是 | 9个源表选项，保留业务场景说明 |
| 10 部署方式 | asset_deployment | 单选/详细说明 | 是 | SaaS、私有化及其他；未决定时保留原文待确认 |
| 11 增值服务 | asset_value_services | 多选/补充说明 | 否 | 6项服务及品牌、型号、接口、定制说明 |
| 12 系统落地时间 | asset_launch_time | 单选/详细说明 | 否 | 5个标准选项及其他；可记录具体日期 |
| 13 需求文件 | asset_requirement_documents | 多行文字 | 否 | 文件名、是否已有、共享链接；原文件上传待扩展 |
| 14 信息提交时间 | submitted_at | 系统初值/可编辑文字 | 是 | 创建产品记录时自动记录北京时间，表示首次录入时间 |

源表「其他」或输入具体情况的题目使用工作台既有的「其他/详细说明」或多选补充说明交互。未采集的选填项可保持为空。

## 选择项

- 资产业态：写字楼、产业园区、社区商业、购物中心、公寓/公租房、专业市场、其他。
- 在租客户数量：50户以下、50-200户、200-500户、500-1000户、1000户以上，以及详细说明。源表在200、500、1000户处存在边界重叠，暂不改写边界；精确数量通过原文保留并待人工确认。
- 痛点：资产盘点不清、招商管理未闭环、经营数据不准/不及时、业财一体建设需求、客户服务能力不足、运营重复性劳动多、多系统数据孤岛、经营决策缺乏数据支持、其他。原表括号中的场景说明和系统对应关系是背景说明，不是自动方案承诺。
- 部署：SaaS、私有化，以及其他/详细说明。源表的「SaaS单项目年费2.6万元起」「私有化客单价通常100万元以上」保留在字段配置的来源备注中，未据此实现报价。
- 增值服务：业务咨询顾问、自动开票、电子签章、硬件对接、软件对接、功能开发，支持补充软硬件品牌型号及定开要求。
- 落地时间：越快越好、3个月内、半年内、1年内、没有明确要求/未立项，以及其他/详细说明。

## 使用方式

启动工作台，在项目中心创建项目并选择「资产管家」，或在已有项目中新增该产品。

1. 选择直接手填、粘贴调研文字稿，或导入项目级录音转写稿。
2. 在信息核对页查看提取结果、来源依据与缺失项，补充并保存。
3. 预览最终结构化结果，确认必填校验通过。
4. 勾选「客户调研结果」，生成Markdown和HTML，进入结果中心查看或打包下载ZIP。

人工修改字段继续沿用保护机制，重解析时不覆盖。首次录入时间也受保护，与客户期望上线时间分开。资产客户专属字段独立保存于产品实例，不自动覆盖项目中心的信息；公共项目名称会同步供同项目其他管家使用。

## 实现位置

- `workbench/config/products/asset_butler/`：产品身份、字段组装、生成物及模板。
- `workbench/config/field_packs/asset_survey.json`：资产客户字段、选项、来源口径和提取提示。
- 公共能力仅增加显式配置项：复用分组显示名覆盖、系统时间初值、允许提取明示0、整数约束、选择题未决词保护、多选题按原行保留及小句否定判断；其他产品未声明时保持既有行为。
- `workbench/samples/asset_butler/`：脱敏完整/缺失文字稿。
- `workbench/tests/test_asset_butler.py`：独立临时数据库下的主流程、ZIP、时间保护、数据隔离、边界与校验测试。

- 原有安全管家主流程自检：89/89通过。
- 全量单元测试：82/85通过；另有3项设备/能源问题未在本次修改范围内处理。设备的两项失败来自共用核对模板中`selected_category.value.items`被Jinja解析为字典方法；能源的一项失败来自旧样例设备名称不在当前候选项内。这些失败位置本次未改动。
- 浏览器：已确认资产产品入口、核对页、5分组预览；修改增值服务多选后刷新仍恢复且标为人工确认；生成客户调研结果成功，结果中心显示MD/HTML查看与下载入口。测试使用隔离数据库。

本机已保存预览页和结果中心的验证截图；验证素材不随源码发布。
