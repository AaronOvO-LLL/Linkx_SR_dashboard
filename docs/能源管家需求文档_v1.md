## 0. 文档定位与协作方式

### 0.1 定位

本文档定义「能源管家」作为灵石解决方案工作台**新增产品模块**的首版需求。能源管家不是独立系统，必须严格沿用现有工作台架构（`workbench/ARCHITECTURE.md`）：产品配置化接入、复用公共字段包、复用项目级录音转写资产、复用现有页面流程。

### 0.2 需求基线原则

- 本文档是后续 Agent 工作的需求基线；已确认需求与待确认假设必须明确分开（分别见 §10、§11、§12）。
- 任何 Agent 发现冲突或信息不足时提出问题，不得自行补写为已确认需求。
- 执行 Agent 的方案和代码不能反向覆盖需求文档；确需调整先走需求确认。
- 评审签字后本文档转为企业基线；变更由需求负责人确认并升版本号。

## 1. 文档目的

定义能源管家首版的业务范围、字段模型、准入规则、产出物与验收标准，作为交互设计、技术设计、开发和测试的统一输入。首版目标：在一个连续流程中完成「准入判断 → 设备清单录入 → 运行现状调研 → 导出设备清单 Excel」。

## 2. 产品定位与目标

### 2.1 定位

能源管家 = **空调冷站节能管理**：摸清项目冷站"能管哪些设备"（硬件底子）与"现在怎么管"（运行基线），为节能空间分析与方案设计提供输入。

- 产品标识：`energy_butler`（已在 `safety_butler/product.json` 的 `planned_products` 中预留）。
- 产品矩阵位置：与安全管家、消防管家、设备管家并列；公共信息（项目基本情况/项目资料/物业信息）复用公共字段包，一次定义、多处复用，禁止复制漂移。

### 2.2 首版成功标准

用户可以在现有工作台连续流程中：

1. 创建或选择项目，完成项目级录音转写（或直接粘贴文字稿）。
2. 在项目中新增「能源管家」产品，导入转写稿。
3. AI 提取准入字段、设备清单与运行现状字段，用户人工校正与补填。
4. 系统按规则给出准入结论；不通过时明确展示「无法匹配该产品」。
5. 通过时预览结构化踏勘结果，导出设备清单 Excel。

## 3. 核心业务流程

### 3.1 三步业务模型

```text
第一步 准入判断（必填字段 + 规则校验）
   │  结论：无法匹配该产品 → 展示结论，阻断生成与导出
   ↓ 通过
第二步 设备清单（table 字段，必填，AI 提取/手工录入）
   ↓
第三步 运行现状 10 问（全部选填）
   ↓
产出：设备清单 Excel（首版）；价值卡片（规则另议，见 §6.2）
```

### 3.2 与现有页面流程的映射

完全复用现有页面，不新增页面类型：

| 现有页面 | 能源管家用途 |
|---|---|
| 项目概览 | 新增能源管家产品实例 |
| 调研输入 | 导入项目级转写稿 / 粘贴文字稿 |
| 信息核对 | 准入字段确认、设备清单表格增删行、10 问补填；准入不通过时展示结论横幅 |
| 预览与生成 | 预览结构化结果，勾选并生成产出物 |
| 结果中心 | 查看/下载设备清单 Excel、ZIP |

### 3.3 准入判断的位置

准入判断在踏勘流程内由「字段提取 + 产品级规则校验」完成（沿用安全管家"纯模拟 → 显示无法配置安全管家"的模式），**不做独立售前 checklist**。

## 4. 字段模型

字段本体存放于新字段包 `config/field_packs/energy_survey.json`（scope=product）；产品组装清单 `config/products/energy_butler/fields.json` 引用：`common_project`、`common_docs`、`common_property`、`energy_survey`。分组顺序：`basic → docs → property → energy_eligibility → energy_equipment → energy_operation`。

### 4.1 第一步：准入字段（组 energy_eligibility，必填）

| 字段 key | 标签 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `energy_system_types` | 项目空调系统类型（可多选） | multiselect | 是 | 选项见下 |
| `energy_fee_over_1m` | 可改造部分的空调电费是否大于100万？ | select（是/否） | 是 | 选择题口径，不追问数据来源 |

`energy_system_types` 选项（5 项）：

| 选项值 | 是否计入可改造部分 |
|---|---|
| 水冷机组中央空调（无冰/水蓄冷） | ✅ |
| 中央空调（带冰蓄冷或水蓄冷辅助） | ❌ 无基础 |
| VRV（末端面板可被 BA 控制且 BA 正常运行） | ✅ |
| VRV（无 BA 或 BA 不正常） | ❌ |
| 其他系统（风冷机组等） | ❌ |

### 4.2 准入规则（产品级跨字段校验）

- **R1**：`energy_system_types` 未包含任一 ✅ 选项 → 结论「无法匹配该产品」。
- **R2**：`energy_fee_over_1m` = 否 → 结论「无法匹配该产品」。
- 结论触发时：信息核对页与预览页展示结论横幅「无法匹配该产品」，**阻断产出物生成与导出**；字段数据保留，用户修改系统类型或电费回答后结论自动解除。
- 可改造部分 = 所选 ✅ 选项的并集；第二步设备清单只覆盖可改造部分的设备。
- 规则实现位置遵循安全管家既有先例（产品作用域校验，不写死在页面）。

### 4.3 第二步：设备清单（组 energy_equipment，必填）

字段 `energy_equipment_list`，类型 `table`（字段模型既有类型，首个业务实例），至少 1 行。

**列定义（9 个录入列 + 系统序号）：**

| 列 key | 列名 | 类型 | 行内必填 | 说明 |
|---|---|---|---|---|
| （系统生成） | 序号 | 自动编号 | — | 按行序自动生成，全表连续 |
| `supply_area` | 供冷区域 | text | 是 | 层级第一级，如 冷却塔 / 55F空调机房 / 板换间 / 公区VRV |
| `building` | 楼栋 | text | 是 | 层级第二级（机房），如 东塔55F |
| `equipment` | 设备 | text | 是 | 如 冷水主机 / 冷却塔循环泵 / 冷冻水泵 / 办公冷却塔 / 公区VRV |
| `brand` | 品牌 | text | 否 | 如 约克 / 塞莱默 / 马利 |
| `power_kw` | 功率(KW) | number | 否 | |
| `cooling_kw` | 制冷量(KW) | number | 否 | 仅冷水主机填写 |
| `quantity` | 数量 | number | 是 | VRV 行填套数 |
| `freq_type` | 工/变频 | select | 否（新行默认「待确认」） | 三值：变频 / 定频 / 待确认 |
| `remark` | 备注 | text | 否 | 用户自由填写特殊点；VRV 行写接入范围概括 |

**填写规则：**

- 层级：供冷区域 → 楼栋(机房) → 设备行；同类设备不同规格**分行**。
- 板式换热器**不登记**。
- VRV 一行概括：数量=套数，备注=接入范围一句话（如"每层公区有一套，只对接公区VRV"）。
- 支持 AI 从文字稿提取多行（`extract.mode=table` 既有能力）与手工增删行。

### 4.4 第三步：运行现状 10 问（组 energy_operation，全部选填）

| # | 字段 key | 标签 | 类型 | 粒度 |
|---|---|---|---|---|
| 1 | `energy_schedule` | 平时开关机时间（制冷季几点到几点、非制冷季几点到几点）？人工操作还是系统操作？ | textarea | 项目 |
| 2 | `energy_season_combination` | 非制冷季和制冷季一般怎么搭配设备（几台主机、几台水泵、几个冷却塔）？ | textarea | 按机房逐行 |
| 3 | `energy_pump_frequency` | 水泵一般设定多少频率？多久调节一次？如何评判是否要调节？ | textarea | 项目（单字段，不拆） |
| 4 | `energy_fee_charging` | 空调电费如何向租户收费？ | textarea | 项目（自由文本） |
| 5 | `energy_chiller_adjust` | 根据什么情况决定现场加减主机或调节出水温度？ | textarea | 按机房逐行 |
| 6 | `energy_pump_adjust` | 根据什么情况决定现场加减水泵？ | textarea | 按机房逐行 |
| 7 | `energy_complaints` | 现场哪些地方投诉较多？主要原因？ | textarea | 项目 |
| 8 | `energy_terminal_management` | 末端空调出风口哪些是物业负责开关的？如何管理的？ | textarea | 项目 |
| 9 | `energy_supply_scope` | 冷站供冷区域是哪些楼层？包不包括租户私区？ | textarea | 项目 |
| 10 | `energy_other_difficulties` | 还有哪些管理难点？ | textarea | 项目 |

- 季节口径统一为「制冷季 / 非制冷季」。
- 按机房逐行的字段沿用消防管家多行 textarea 先例：`help`/`ai_hint` 要求"每个机房（楼栋）一行，行首注明机房名"，与设备清单出现的机房对应。
- Q3 不含"是否变频"子问——变频能力以设备清单「工/变频」列为准。

## 5. 输入方式

- 沿用安全/设备管家模式：**录音转写（项目级资产）或粘贴文字稿 → AI 提取 → 人工校正**。
- 录音转写为项目级，一份录音只转写一次，能源管家通过显式「导入」复用共享转写稿。
- 设备清单同时支持信息核对页手工增删行直录。
- ASR 词表：新增产品词表素材 `config/products/energy_butler/asr_terms.json`（冷水主机、冷却塔、板换、VRV、BA、冷冻水泵、冷却塔循环泵、制冷季等），按现行机制合并入项目级词表。

## 6. 产出物

### 6.1 设备清单 Excel（首版核心产出物）

- artifact key：`equipment_list`；格式：`xlsx`。
- 内容：§4.3 设备清单全表，10 列布局与列名对齐参考图；供冷区域、楼栋相邻同值行**合并单元格**（对齐参考图样式）；序号全表连续。
- 文件名：`{项目名称}_能源管家_设备清单_{YYYYMMDD}.xlsx`；同时支持单文件下载与随 ZIP 打包（沿用现有打包流程）。
- 技术约束（ARCHITECTURE §4.3）：xlsx 为新文件格式，**注册独立 renderer**，不在 `generate.py` 中写 artifact key 分支；需新增依赖 `openpyxl`（锁定版本，登记 `requirements.txt` 与 `requirements-prod.txt`）。

### 6.2 价值卡片（规则另议）

- 产出物位预留（artifact key：`value_card`），**内容规则与模板待单独讨论后以需求变更补充**。
- 规则确认前，能源管家首版可生成产出物仅设备清单 Excel；价值卡片入口不开放。

### 6.3 其他产出物

- 首版不做：完整踏勘结果 md/html、费用估算、交付内容、提资基础内容。是否补「完整踏勘结果」见 §11 待确认 P1-3。

## 7. AI 提取要求

- 准入字段：`energy_system_types` 用 enum 提取（含否定守卫：如"没有冰蓄冷"不得误判为带蓄冷）；`energy_fee_over_1m` 用 enum 提取（是/否）。
- 设备清单：`extract.mode=table`，从文字稿抽取多行设备条目；抽不到的列留空（变频未知 → 待确认），不得编造功率/制冷量/数量。
- 10 问：sentence/textarea 提取；按机房逐行字段保留机房编号与行结构，不得合并遗漏。
- 所有提取字段记录值、来源片段、状态、置信等级、提取时间、模板版本（沿用现有机制）。

## 8. 集成方式（严格沿用现有架构）

1. 新建 `config/products/energy_butler/`：`product.json`（version 0.1.0，status 由 planned 转 active 于发布时；capabilities：`text_input`、`audio_asr`、`field_extraction`、`artifact_generation`）、`fields.json`、`artifacts.json`、`templates/`、`asr_terms.json`。
2. 新建字段包 `config/field_packs/energy_survey.json`（scope=product）；公共信息一律引用 common_* 包，禁止复制公共字段。
3. 准入规则 R1/R2 以产品作用域校验实现，页面不写死业务分支。
4. xlsx renderer 注册 + openpyxl 依赖登记（§6.1）。
5. 发布前执行：`python check_config.py energy_butler`、`python check_config.py --strict`、`python -m unittest discover`、`python selftest.py`。
6. 提供至少一份脱敏输入与期望字段结果（含设备清单期望行）。

## 9. 验收场景

- **场景 A（完整主流程）**：含冷站信息的文字稿 → 提取 → 校正 → 准入通过 → 设备清单 3 行以上 → 导出 xlsx，列布局与合并单元格符合参考图。
- **场景 B（准入失败-系统类型）**：文字稿仅含风冷机组/带蓄冷系统 → 展示「无法匹配该产品」，阻断生成；修改字段后结论解除。
- **场景 C（准入失败-电费）**：系统类型合格但电费回答「否」→ 同上结论与阻断。
- **场景 D（表格提取与手录）**：文字稿含多机房多规格设备 → 提取行数与规格分行正确；手工增删行、改列后保存不丢。
- **场景 E（选填缺失）**：10 问全空仍允许生成设备清单 Excel。
- **场景 F（多机房逐行）**：Q2/Q5/Q6 按机房逐行保留，预览与导出可读。
- **场景 G（重新进入）**：退出重进后准入结论、清单行、确认状态恢复。

## 10. 已确认决策（2026-09-28 三轮讨论）

1. 混合系统只取支持部分：水冷机组且无冰/水蓄冷的中央空调、末端面板可被 BA 控制且 BA 正常运行的 VRV；其余系统类型一律不做。
2. 项目没有任何受支持系统 → 直接结论「无法匹配该产品」。
3. 门槛为选择题：「可改造部分的空调电费是否大于100万？」否 → 「无法匹配该产品」；不追问数据来源与边界细节。
4. 带冰蓄冷/水蓄冷辅助的中央空调 → 该系统无基础，不进可改造部分。
5. 设备清单固定 10 列（含系统序号）；备注列用户自由写特殊点。
6. 工/变频三值：变频 / 定频 / 待确认。
7. VRV 一行概括：数量=套数 + 备注写接入范围。
8. 板式换热器不登记。
9. 清单按机房（楼栋）分组；Q2/Q5/Q6 按机房逐个回答。
10. 第三步 10 问全部选填。
11. 季节口径统一「制冷季 / 非制冷季」。
12. Q3 合并为单个自由文本字段（设定频率/调节周期/评判依据）。
13. Q4 自由文本。
14. 删除 Q3 中"是否变频"子问，变频能力以清单「工/变频」列为准。
15. 输入方式同安全/设备管家：录音/文字 AI 提取 + 人工校正。
16. 设备清单为必填；为**产出物**（语音/手工录入后直接导出 Excel），不是单纯输入项。
17. 准入判断在踏勘流程内由字段提取 + 规则校验完成，不做独立售前 checklist。
18. 价值卡片为产出物之一，规则稍后单独讨论。
