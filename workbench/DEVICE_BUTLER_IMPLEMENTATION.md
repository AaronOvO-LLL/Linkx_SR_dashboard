# 设备管家首版实现说明

按《设备管家Demo需求文档.md》接入现有项目、分部访问、录音转写、信息核对、预览与结果中心流程。需求文档已同步到 v0.2：第 15 章补入实现期确认的决策 23-28，第 16 章关闭已决项、保留三项待确认。

- 新增产品 device_butler，版本 0.1.0；引用三个公共字段包及新增的 device_survey（一张表格字段 device_room_survey）。
- 传感器配置规则库落在 `config/products/device_butler/rules.json`（只读配置，rules_version 1.0.0），承载需求文档第 8 章的 7 类空间类型、固定项默认值、变动项与同义词；第 8.5 章排除项不进文件。配电房按决策 C1／微决策 1 取基础版（温湿度 1、摄像头 1），与源 xlsx 的 2／2 不同，以规则库为准。
- 规则计算引擎为新增通用能力 `core/rules.py`：纯函数、不落库、不写产品名分支。职责为规则库自检、同义词归一、固定项物化（幂等）、按计算模式换算、行级问题、界面描述、rule 通道表格抽取。预览与生成时按当下录入重算，因此不存在陈旧派生数据。
- 固定项按决策 23 预填为可编辑表格行，与变动项同表同字段，人工调整走平台既有的保存与确认保护机制。不要某项时把数量改成 0 而不是删行（决策 27）——删掉的行会在下次保存时被重新补出，因为「主动删除」与「尚未补全」在数据上无法区分。
- 提取新增 `rules_table` 模式并已登记进 `config/field_model_schema.json`（schema 1.3.0，同时补齐了表格列属性的契约描述）。rule 与 llm 两个通道提取后统一走 `rules.postprocess`：归一 → 补全固定项 → 有算不出的行就把整张表降为待确认，避免两个通道口径漂移。LLM 通道额外收到规则库的空间类型与物业设备候选项。
- 校验接入 `core/validate.py::rules_issues`：空间类型不在 7 类内、物业设备不在该空间类型规则内、数量非整数或为负、该有数量却留空，都在核对页与生成前拦住；空调机房管网数留空只给 warn、不阻断（微决策 2）。
- Excel 复用工作台既有的 `core/renderers.py` 注册表，新增 `xlsx_dataset` renderer 消费 `ctx['datasets']`，不在 `core/generate.py` 里加格式分支。列标签只在规则库的 `result_columns` 定义一次，`artifacts.json` 仅补宽度与对齐。页眉带项目名称、客户、生成时间、规则库版本与字段模板版本（需求 6.7 可追溯）；`rules_version` 同时写入 ZIP manifest 的 product 段。
- `openpyxl==3.1.5` 已登记进 requirements.txt 与 requirements-prod.txt（本机曾出现两行重复，已合并）。

## 验证

在 workbench 目录执行：

```
python check_config.py --strict
python -m unittest discover
python selftest.py
```

结果：4 个产品配置全部通过 strict 检查；80 项单元测试通过（新增 29 项设备管家测试）；原有 selftest 89/89 通过。

浏览器已走通完整主流程（一部 / 项目「验证-设备管家云澜产业园」）：粘贴 457 字样例文字稿 → rule 通道提取命中 18/18 → 核对页渲染 41 行表格并给出「独立水箱数未确定」拦截 → 人工补 1 后校验通过、状态转为已人工确认 → 预览页展示 4 个分组与产出物 → 生成 Excel 成功 → ZIP 打包目录为 `01_传感器配置清单/`。生成的 xlsx 共 39 行配置，与需求文档 9.2 的列定义和数量口径一致（`3 区`、`1 套`、其余纯数字）。

新增 `tests/test_device_butler.py` 覆盖需求文档第 14 章场景 A-G：完整主流程与 Excel 内容、同类多间拆分（A1）、模糊数量阻断生成（A2）、固定项调整（B3）、排除项不出现、连通水箱由人补独立数（B2）、退出重进恢复、人工确认不被重提取覆盖、以及规则引擎的确定性与金标准回归（`samples/device_butler/expected.json`）。

脱敏样例：`samples/device_butler/full.md`（信息充分）、`missing.md`（数量含糊）、`expected.json`（期望提取行与期望 BOM）。

## 待确认与验证边界

- 核对页目前仍是 4 个输入列（序号／设备房名称／空间类型／物业设备／设备数量／操作），传感器类型与数量只在预览页与 Excel 中出现。需求 6.5 的「勾选／取消物业设备行」与「改数量即刷新传感器列」属于界面改动，按既定做法先出自包含 HTML 静态视觉稿评审，通过后再动 `templates/` 与 `static/`。首版用「数量改 0」替代取消勾选。
- 空间类型与物业设备用文本框录入，靠规则库同义词归一兜底（口语写法如「生活泵房」「生活水箱」会归一到标准名，归一失败则报错提示）。是否改成随空间类型联动的下拉，与上一项一并在静态稿阶段决定。
- rule 通道的表格抽取按「设备房提法切分文本范围 + 同义词最长匹配 + 小句内取数」实现，对样例文字稿准确；自由口语的覆盖率以 LLM 通道为主，rule 通道用于离线回归与 Demo。
- 本轮验证使用离线规则引擎与本地测试数据，未调用付费 LLM／ASR 服务；设备管家热词尚未合入项目级 `config/asr_terms.json`（该合并目前仍是人工动作）。
- 未做跨设备房的传感器汇总（决策 D3）；不含价格、型号与线缆列（微决策 5）。
