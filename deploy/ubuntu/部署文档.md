# 灵石解决方案工作台 · Ubuntu 22.04 部署与运维说明

> 目标服务器：腾讯云轻量应用服务器（Ubuntu 22.04 LTS）
> 架构：Nginx（对外） → Waitress（单进程多线程，内网 127.0.0.1:8000） → Flask 应用
> 域名：hao-rizon.com（**尚未备案**）

## 关于备案（先读这一段）

大陆腾讯云会**拦截未备案域名**通过 80/443 的访问。`ping` 通只代表 DNS 解析正确，不代表能开网站。因此分两阶段：

- **阶段一（现在，无需备案）**：用 `http://服务器公网IP:8770` 访问，刻意避开 80/443。
- **阶段二（备案通过后）**：切到 `https://hao-rizon.com`，Let's Encrypt 证书 + 强制跳转。

两个阶段**应用代码完全不变**，只改 Nginx 配置。

## 阶段一：IP + HTTP 上线

### 1. 登录服务器、装基础软件
```bash
ssh root@你的服务器公网IP
apt update && apt upgrade -y
apt install -y python3 python3-venv python3-pip nginx
```

### 2. 上传代码
把本地 `灵石解决方案工作台/` 整个目录传到服务器 `/opt/lingshi-workbench/`。
（可用 `scp -r`、宝塔面板、或 git clone。**不要上传 `data/` 里的真实录音、数据库、密钥**。）
最终应存在 `/opt/lingshi-workbench/workbench/app.py`。

### 3. 建虚拟环境、装生产依赖
```bash
cd /opt/lingshi-workbench
python3 -m venv venv
./venv/bin/pip install --upgrade pip
./venv/bin/pip install -r workbench/requirements-prod.txt
```

### 4. 配置环境变量（密钥）
```bash
mkdir -p /etc/lingshi
cp workbench/deploy/ubuntu/lingshi.env.example /etc/lingshi/lingshi.env 2>/dev/null \
  || cp deploy/ubuntu/lingshi.env.example /etc/lingshi/lingshi.env
# 生成并填入会话密钥
python3 -c "import secrets; print(secrets.token_urlsafe(48))"
nano /etc/lingshi/lingshi.env       # 填 LS_SESSION_SECRET、DEEPSEEK_API_KEY、腾讯云 ASR/COS 变量
chmod 600 /etc/lingshi/lingshi.env  # 务必收紧权限
```

### 5. 数据目录权限（systemd 以 www-data 运行）
```bash
mkdir -p /opt/lingshi-workbench/workbench/data
chown -R www-data:www-data /opt/lingshi-workbench/workbench/data
```
> `config/` **无需**对服务进程开放写权限，保持 root 只读即可（最小权限）。
> 应用运行时唯一需要回写的配置是分部口令，它落在 `data/departments.json`。

### 5.1 分部口令是怎么工作的（上线前必读）
- `config/departments.json` 是**只读种子**，里面是初始口令 `000000`。
- 首次启动时应用会把种子**哈希**后写入 `data/departments.json`（权限 600），此后只认这份文件。
- 应用内「修改密码」改的是 `data/departments.json`，**不会**回写种子。因此改 `config/departments.json` 对已初始化的环境无效。
- 明文口令不落盘：即使 `data/departments.json` 泄露，也拿不到可用口令。
- **忘记口令的唯一恢复手段**：`systemctl stop lingshi-workbench` → 删除 `data/departments.json` → 重启，
  全部 5 个分部会回到初始口令 `000000`（`changed` 标记同时清零），然后重新登录改密。

### 6. 安装 systemd 服务
```bash
cp deploy/ubuntu/lingshi-workbench.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now lingshi-workbench
systemctl status lingshi-workbench     # 应为 active (running)
journalctl -u lingshi-workbench -f     # 看实时日志
```
> 若部署路径不是 `/opt/lingshi-workbench`，请先编辑 service 文件里的 `WorkingDirectory` 与 `ExecStart` 路径。

### 7. 配置 Nginx（阶段一）
```bash
cp deploy/ubuntu/nginx-phase1-ip-http.conf /etc/nginx/sites-available/lingshi
ln -sf /etc/nginx/sites-available/lingshi /etc/nginx/sites-enabled/lingshi
rm -f /etc/nginx/sites-enabled/default
nginx -t && systemctl reload nginx
```

### 8. 放行端口
- **腾讯云控制台 →「防火墙」→ 添加规则**：放行 TCP `8770`（阶段二再放行 80/443）。
- 服务器内若启用了 ufw：`ufw allow 8770/tcp`。

### 9. 验证
浏览器访问 `http://你的服务器公网IP:8770`，应看到分部登录页。
登录页**不再显示任何初始口令**，初始口令是 `000000`（见 5.1）。

```bash
ls -l /opt/lingshi-workbench/workbench/data/departments.json   # 应存在且为 -rw-------
journalctl -u lingshi-workbench -n 30                          # 应看到「安全警告：仍在使用初始口令」
```

**登录后立即到「修改密码」把 5 个分部的初始口令 `000000` 全部改掉。**
每改完一个，重启后日志里的告警名单就少一个；5 个全改完则告警消失。

## 阶段二：备案通过后升级到 HTTPS

1. 确认 `hao-rizon.com`（及 `www`）的 A 记录指向服务器公网 IP，且**已完成 ICP 备案**。
2. 腾讯云防火墙放行 TCP `80` 与 `443`。
3. 申请证书并自动改写 Nginx：
```bash
apt install -y certbot python3-certbot-nginx
certbot --nginx -d hao-rizon.com -d www.hao-rizon.com
```
   或手动启用本仓库的阶段二配置：
```bash
cp deploy/ubuntu/nginx-phase2-https.conf /etc/nginx/sites-available/lingshi
nginx -t && systemctl reload nginx
```
4. （可选）关闭阶段一的 8770：从 Nginx 配置移除 `listen 8770`，并在腾讯云防火墙删掉该规则。
5. **打开 Secure Cookie**：编辑 `/etc/lingshi/lingshi.env`，把 `LS_COOKIE_SECURE=false` 改为 `true`，
   然后 `systemctl restart lingshi-workbench`。（HTTPS 已生效，此时开启才安全。）
6. 验证 `https://hao-rizon.com` 可访问，且 `http://` 自动跳转 `https://`。
> 应用通过 Nginx 转发的 `X-Forwarded-Proto=https` 感知真实协议，无需改代码。

## 日常运维

- **看日志**：`journalctl -u lingshi-workbench -n 200 -f`
- **重启**：`systemctl restart lingshi-workbench`（改完 env 或代码后）
- **改代码后发布**：替换文件 → `systemctl restart lingshi-workbench`
- **备份**（SQLite + 生成物）：建议加 cron 每日打包 `workbench/data/`（含 `workbench.db`），异地保存：
```bash
tar czf /opt/backup/lingshi-$(date +%F).tar.gz -C /opt/lingshi-workbench/workbench data
```
- **单进程约束**：ASR 转写走进程内后台线程、SQLite 单机单写，**不要**改用 gunicorn 多 worker，否则会丢在途任务、写并发出错。
- **口令备份**：`data/departments.json` 在 `data/` 里，所以上面的备份已经包含它。恢复备份会同时恢复当时的口令，属预期行为。

- [ ] `systemctl status lingshi-workbench` 为 active
- [ ] 腾讯云防火墙已放行对应端口（阶段一 8770 / 阶段二 80、443）
- [ ] 浏览器能打开登录页，且页面上看不到任何初始口令
- [ ] `data/departments.json` 已生成、权限 600、内容只有 `password_hash`
- [ ] 5 个分部初始口令 `000000` 已全部修改（启动日志不再出现安全警告）
- [ ] （阶段二）域名已备案、HTTPS 可访问且强制跳转
